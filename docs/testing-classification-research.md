# 软件测试分类体系完整调研报告

> 基于 ISTQB、IEEE 标准及行业最佳实践整理
> 覆盖八大项目类型：静态网站 · SaaS/全栈Web · 桌面端应用 · 移动App · 小程序 · 后端API服务 · CLI工具 · npm包/库

---

## 一、按测试阶段划分

### 1.1 各阶段定义与内容

| 测试阶段 | 英文 | 核心定义 | 具体包含内容 |
|---------|------|---------|------------|
| **单元测试** | Unit Testing | 对软件的最小可测试单元（函数、方法、类、模块）进行验证，确保其行为符合预期 | • 函数/方法级逻辑正确性验证<br>• 边界值测试（最大值、最小值、空值、零值）<br>• 分支覆盖（if/else、switch/case 全路径）<br>• 异常路径测试（抛出异常、返回 error）<br>• Mock/Stub 外部依赖（数据库、网络、文件系统）<br>• 纯函数与副作用函数分离测试<br>• 数据结构和算法正确性 |
| **集成测试** | Integration Testing | 验证多个模块/组件之间的交互是否按预期工作，重点关注接口和通信 | • 模块间接口调用（函数签名、参数传递）<br>• API 端点集成（请求/响应格式、状态码）<br>• 数据库集成（CRUD、事务、连接池）<br>• 外部服务集成（第三方 API、消息队列、缓存）<br>• 微服务间通信（RPC、gRPC、事件总线）<br>• 数据流完整性（A模块输出 → B模块输入）<br>• 协议兼容性（HTTP、WebSocket、gRPC、GraphQL） |
| **系统测试** | System Testing | 将完整的软件系统作为一个整体进行测试，验证其是否满足需求规格说明 | • 端到端业务流程（完整用户旅程）<br>• 功能完整性（所有需求点均已实现）<br>• 非功能性需求验证（性能、安全、可用性）<br>• 跨模块数据一致性<br>• 错误处理与恢复机制<br>• 系统配置与初始状态验证<br>• 全量数据导入/导出验证 |
| **验收测试** | Acceptance Testing | 由用户/客户或业务代表执行，确认系统是否满足业务需求和验收标准 | • 用户验收测试（UAT）—— 真实用户操作场景<br>• Alpha 测试 —— 内部人员模拟用户<br>• Beta 测试 —— 小范围真实用户试用<br>• 合同验收测试 —— 逐条核对合同条款<br>• 法规验收测试 —— 满足行业监管要求<br>• 业务场景验证（核心流程走通）<br>• 用户故事/用例验收 |
| **回归测试** | Regression Testing | 在代码变更后重新执行既有测试，确保新代码没有破坏已有功能 | • 全量回归（所有已有测试用例全跑）<br>• 选择性回归（仅影响模块的测试）<br>• 冒烟测试先行（快速验证核心功能）<br>• 自动回归 vs 手动回归<br>• 基线对比（截图、API 响应、性能指标）<br>• 持续集成中的回归流水线<br>• 缺陷修复验证（fix → 确认 → 回归） |

### 1.2 按项目类型评级（按测试阶段）

| 项目类型 | 单元测试 | 集成测试 | 系统测试 | 验收测试 | 回归测试 |
|---------|:-------:|:-------:|:-------:|:-------:|:-------:|

| **桌面端应用** | **必须** | **必须** | **必须** | 推荐 | **必须** |
| **移动App** | 推荐 | **必须** | **必须** | **必须** | **必须** |
| **小程序** | 推荐 | 推荐 | **必须** | **必须** | **必须** |
| **后端API服务** | **必须** | **必须** | **必须** | 推荐 | **必须** |

- **必须** —— 不执行则产品质量不可控，属于行业基准线

- **可选** —— 视项目需求、预算、时间决定是否执行
- **不需要** —— 该类型项目通常不适用此测试

## 二、按测试目标划分

### 2.1 各目标定义与内容

| 测试目标 | 英文 | 核心定义 | 具体包含内容 |
|---------|------|---------|------------|
| **功能测试** | Functional Testing | 验证软件功能是否按照需求规格说明书正确实现 | • 所有功能点逐一验证（需求覆盖）<br>• 输入验证（合法/非法/边界/异常输入）<br>• 业务规则验证（折扣计算、状态流转、权限判定）<br>• 数据校验（格式、长度、唯一性、关联性）<br>• 状态机测试（页面状态、订单状态、用户状态）<br>• 正例测试（Happy Path）<br>• 反例测试（异常路径、错误场景）<br>• 等价类划分与边界值分析<br>• 因果图/决策表测试 |
| **性能测试** | Performance Testing | 评估系统在特定负载下的响应速度、吞吐量、稳定性和资源消耗 | • 负载测试（Load Testing）—— 正常负载下的表现<br>• 压力测试（Stress Testing）—— 超出极限负载的表现<br>• 容量测试（Capacity Testing）—— 系统最大承载能力<br>• 耐久性测试（Endurance/Soak Testing）—— 长时间运行稳定性<br>• 峰值测试（Spike Testing）—— 突发流量冲击<br>• 响应时间（P50/P95/P99 延迟）<br>• 吞吐量（TPS/QPS）<br>• 资源利用率（CPU、内存、磁盘IO、网络IO）<br>• 数据库连接池/线程池瓶颈分析<br>• 前端性能（LCP、FCP、TTI、CLS、FID）<br>• 启动时间（桌面/移动App冷启动和热启动）<br>• 内存泄漏检测 |
| **安全性测试** | Security Testing | 识别系统安全漏洞，确保数据的机密性、完整性、可用性 | • 渗透测试（Penetration Testing）<br>• SQL 注入、XSS、CSRF、SSRF 测试<br>• 认证与授权测试（越权访问、JWT 弱密钥、Session 固定）<br>• OWASP Top 10 全量检查<br>• 敏感数据泄露检测（日志、错误信息、响应头）<br>• HTTPS/TLS 证书与加密配置<br>• API 鉴权与速率限制<br>• 文件上传安全（类型绕过、路径穿越）<br>• 依赖库漏洞扫描（SBOM、CVE 检查）<br>• 安全配置审计（CSP、CORS、HSTS、X-Frame-Options）<br>• 日志审计与入侵检测<br>• 社会工程学测试（钓鱼邮件等） |
| **兼容性测试** | Compatibility Testing | 验证软件在不同环境（硬件、操作系统、浏览器、设备）下能否正常运行 | • 浏览器兼容性（Chrome、Firefox、Safari、Edge、移动端浏览器）<br>• 操作系统兼容性（Windows、macOS、Linux、iOS、Android）<br>• 屏幕分辨率/尺寸适配（响应式布局、断点测试）<br>• 设备兼容性（手机型号、平板、折叠屏、不同 DPI）<br>• 网络环境兼容性（WiFi、4G/5G、弱网、离线模式）<br>• 软件版本兼容性（Node.js 版本、Python 版本、JDK 版本）<br>• 第三方依赖兼容性（数据库版本、中间件版本）<br>• 字体渲染与国际化支持<br>• 硬件架构兼容性（x86 vs ARM、32-bit vs 64-bit） |
| **易用性测试** | Usability Testing | 评估软件的用户体验是否直观、高效、愉悦，是否符合用户习惯 | • 用户操作流程合理性（任务完成路径最短）<br>• 导航与信息架构清晰度<br>• 一致性检查（术语、图标、按钮、交互方式统一）<br>• 错误提示与反馈机制（Toast、弹窗、表单验证提示）<br>• 首次使用引导（Onboarding 流程）<br>• 可学习性（新用户完成任务的效率）<br>• 效率（熟练用户的操作速度）<br>• 满意度（用户主观评价、NPS、SUS 评分）<br>• 认知负荷评估（信息密度是否合理）<br>• 无障碍性（Accessibility）—— 色盲、屏幕阅读器支持<br>• 交互动效流畅度<br>• 用户任务成功率与错误率 |

## 三、其他专项测试

### 3.1 专项测试完整列表

| 专项测试 | 英文 | 定义 | 适用场景 |
|---------|------|------|---------|
| **UI界面测试** | UI Testing | 验证界面元素是否按设计稿渲染，包括布局、颜色、字体、间距、图标、交互反馈 | 所有带图形界面的项目 |
| **安装/部署测试** | Installation/Deployment Testing | 验证软件的安装、卸载、升级、降级、多实例部署流程是否正常 | 桌面端应用、CLI工具、后端服务、SaaS 部署 |
| **文档合规性检查** | Documentation Compliance | 检查用户手册、API文档、README、Changelog 是否完整、准确、一致 | 所有项目（尤其 npm包、API服务、CLI工具） |
| **国际化/本地化测试** | i18n/l10n Testing | 验证多语言、多区域、多货币、多时区支持是否正确 | SaaS、移动App、桌面端应用 |
| **可访问性测试** | Accessibility Testing | 确保残障人士（视障、听障、行动障碍）可以使用软件 | 面向公众的 SaaS、Web 站点、移动App（法规要求） |
| **异常/恢复测试** | Error Recovery Testing | 测试系统在崩溃、断电、断网后能否自动恢复或手动恢复 | 后端服务、桌面端应用、数据库密集型应用 |
| **配置测试** | Configuration Testing | 验证不同配置组合下系统的行为 | 桌面端应用、CLI工具、后端服务 |
| **冒烟测试** | Smoke Testing | 每次构建后快速验证核心功能是否可用，决定是否进入详细测试 | 所有项目（CI/CD 入口） |
| **可靠性测试** | Reliability Testing | 评估系统在长时间运行下的无故障概率（MTBF、MTTR） | 后端服务、桌面端应用、IoT 固件 |
| **故障转移/灾难恢复测试** | Failover/DR Testing | 测试主备切换、多数据中心容灾、数据备份恢复流程 | 后端服务、SaaS |
| **API测试** | API Testing | 对 API 接口的请求/响应、鉴权、限流、幂等性、版本兼容性进行测试 | 后端API、SaaS 前端调用后端、移动App 调用后端 |
| **数据一致性测试** | Data Integrity Testing | 验证数据在写入、读取、迁移、备份、同步过程中的完整性 | 数据库密集型系统、分布式系统 |
| **端到端测试** | E2E Testing | 模拟真实用户的完整操作流程，从前端到后端到数据库的全链路验证 | SaaS、移动App、桌面端应用 |
| **探索性测试** | Exploratory Testing | 测试人员凭经验自由探索，发现未定义的缺陷 | 所有项目（作为补充手段） |
| **A/B测试** | A/B Testing | 同时运行两个版本，对比用户行为数据以决定哪个版本更优 | SaaS、移动App、Web（功能迭代验证） |
| **混沌测试** | Chaos Testing | 在生产环境或类生产环境故意注入故障，验证系统弹性 | 后端服务、微服务架构 |
| **压力测试** | Stress Testing | 超出系统设计极限的负载，观察系统行为（降级/崩溃/恢复） | 后端服务、API服务 |
| **负载测试** | Load Testing | 模拟预期用户量的正常负载，验证性能指标 | 后端服务、API服务、SaaS |
| **容量测试** | Capacity Testing | 找到系统能承载的最大用户数/数据量，帮助规划扩容 | 后端服务、SaaS、数据库系统 |
| **耐久性测试** | Endurance Testing | 长时间运行（72h+）检查内存泄漏、资源耗尽、性能衰减 | 后端服务、桌面端应用 |
| **灰度发布测试** | Canary Testing | 新版本仅对部分用户开放，监控指标后再全量发布 | SaaS、后端服务 |
| **竞品对比测试** | Competitive Benchmarking | 与竞品进行功能、性能、易用性对比 | 商业产品（所有项目类型） |
| **合规性测试** | Compliance Testing | 验证是否符合行业法规（GDPR、HIPAA、PCI-DSS、ISO 27001） | 面向金融、医疗、政务的系统 |
| **移动特有测试** | Mobile-Specific | 电量消耗、网络切换、来电中断、推送通知、手势操作、传感器 | 移动App、小程序 |
| **桌面特有测试** | Desktop-Specific | 多窗口管理、系统托盘、快捷键、文件拖拽、右键菜单、多显示器 | 桌面端应用 |

## 四、按项目类型的完整测试策略矩阵

### 4.1 静态网站

| 测试类别 | 具体测试项 | 评级 | 说明 |
|---------|-----------|:----:|------|
| **阶段** | 单元测试 | 不需要 | 纯静态页面无逻辑可测 |
| | 集成测试 | 不需要 | 无后端集成 |
| | 系统测试 | 推荐 | 检查全站链接、资源加载、SEO |
| | 验收测试 | 可选 | 客户确认视觉和内容 |
| | 回归测试 | 推荐 | 修改后检查有没有破坏已有页面 |

## 七、总结

### 核心原则

1. **测试投入与项目风险成正比** —— 金融系统、医疗系统、电商平台的测试投入远高于个人博客
2. **测试金字塔原则** —— 底部单元测试最多，越往上越少
3. **左移测试** —— 测试越早介入，修复成本越低
4. **自动化优先** —— 重复性测试自动化，探索性测试保留人工
5. **持续测试** —— 测试嵌入 CI/CD 流水线，每次提交都运行

### 按项目类型最低要求（最小可行测试策略）

| 项目类型 | 最低要求（MVP 阶段） |
|---------|-------------------|
| **静态网站** | 兼容性测试 + UI 渲染测试 + 链接检查 |
| **SaaS/全栈Web** | 单元测试 + 集成测试 + E2E 核心流程 + API 安全测试 |
| **桌面端应用** | 单元测试 + 集成测试 + 安装/卸载测试 + 兼容性测试 |
| **移动App** | 集成测试 + 移动特有测试 + 核心功能测试 + 兼容性测试 |
| **小程序** | 功能测试 + 兼容性测试 + 支付流程测试 |
| **后端API服务** | 单元测试 + API 集成测试 + 性能基准测试 + 安全扫描 |
| **CLI工具** | 单元测试 + 参数组合测试 + 跨平台测试 |
| **npm包/库** | 单元测试 + 多版本兼容性测试 + 类型定义测试 |

---

*本报告基于 ISTQB 大纲、ISO/IEC 25010 质量模型、OWASP 标准及行业最佳实践整理，可作为项目测试策略制定的参考框架。*
